# Security Policy

Security and privacy are core research concerns for EXPANSE.

## Reporting a vulnerability

Please do not publish exploitable vulnerability details, credentials, private keys, personal data, or sensitive network topology in public issues.

Use GitHub's private vulnerability reporting feature if it is enabled for this repository. If it is unavailable, contact the repository maintainer through a trusted private channel before disclosing technical details publicly.

When reporting, include where possible:

- affected component and version;
- a concise description of the issue;
- impact and plausible attack conditions;
- reproduction steps or a minimal proof of concept;
- suggested mitigation.

Do not include real secrets or data belonging to other people.

## Scope

This policy covers security issues in EXPANSE-maintained code, documentation, configurations, and experimental infrastructure. Third-party vulnerabilities should be reported to the relevant upstream project in accordance with its security policy.

## Research environment

Experiments should be conducted on systems and networks that the researcher owns or is explicitly authorized to test. Avoid tests that disrupt public infrastructure, expose participants, or collect data without consent.

## Coordinated disclosure

Please allow maintainers and affected upstream projects reasonable time to assess and address a report before public disclosure. The appropriate timeline depends on severity, exploitability, and coordination requirements.
