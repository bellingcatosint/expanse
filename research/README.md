# Research Programme

This directory contains research notes, technology assessments, and evidence reviews.

## Research tracks

| Track | Focus | Initial questions |
|---|---|---|
| Self-healing networks | Recovery from node and link failures | How is failure detected? How quickly can useful paths and services recover? |
| DTN and data delivery | Store-carry-forward communication | Which data should be buffered, prioritized, expired, or replicated? |
| Heterogeneous transport | Cooperation across different media | How can IP, radio, LoRa, satellite, and intermittent links be bridged safely? |
| Autonomous routing | Distributed route selection | Which routing responsibilities belong to each layer? |
| Privacy and trust | Identity, metadata, authentication, key management | What information is exposed, to whom, and under which assumptions? |
| Persistent edge services | Local service continuity | Which services and datasets should remain available during isolation? |

## Suggested note structure

Each substantial research note should document:

1. Research question and scope.
2. Current evidence and source quality.
3. Relevant standards and implementation details.
4. Technical constraints and known incompatibilities.
5. Hypotheses and unresolved questions.
6. Proposed experiments.
7. Findings, confidence, and limitations.
8. Date and review status.

## Evidence discipline

Use the evidence labels defined in the root README and CONTRIBUTING guide. Record the date of review for fast-moving software and standards. Do not treat a project's marketing description as proof of behaviour under EXPANSE test conditions.
